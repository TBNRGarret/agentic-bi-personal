## 3. Technical Challenges & Resolutions

- **Challenge**: The DataHub quickstart metadata stack is heavy and can consume up to 8GB of RAM, which is problematic for deployment on a resource-constrained VPS or local dev setup.
- **Resolution**: Configured JVM tuning constraints (JVM Heap memory limits: Elasticsearch - 1GB, Kafka - 512MB, Zookeeper - 256MB, GMS - 1GB) within `start-datahub.ps1` to keep the footprint lightweight (~12.5GB RAM total buffer).

- **Challenge**: Initial git push for `git subtree push` rejected updates on remote `agentic-bi` due to divergent commit histories between local subtree splits and initialized remote repos.
- **Resolution**: Performed a manual `git subtree split` to a temporary branch, force-pushed the split branch to remote `hoangvl/sprint-2-airflow-ui` and `hoangvl/epic1-pipeline` branches, and cleaned up the temporary branch.

- **Challenge**: The AI agent requires table schema metadata dynamically to formulate accurate SQL queries without hardcoding tables in prompts.
- **Resolution**: Implemented keyword-based relevance scoring inside `DataHubClient.get_schema_context_for_question()` to extract only the top relevant schemas and inject them dynamically into prompts, saving token usage.
