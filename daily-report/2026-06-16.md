## 2. Key Work Completed

### 2.1 Observation Service Scaffold

Added a FastAPI backend under `src/backend` with the Sprint 2 API surface:

| Endpoint | Purpose |
| :--- | :--- |
| `GET /health` | Service status and observability configuration flags |
| `POST /chat` | AI-style terminal agent v1 using a deterministic command planner |
| `POST /terminal/run` | Safe allowlisted terminal API |
| `POST /query` | Read-only ClickHouse query endpoint |
| `GET /schema` | ClickHouse schema snapshot for `vsf_raw`, `vsf_stg`, and `vsf_mart` |

The `/chat` endpoint is intentionally a v1 shell: it validates the backend, tool-call, logging, Langfuse, and SigNoz paths before introducing a real LLM planner.

### 2.2 Terminal API Safety

Implemented a safe terminal runner with:

- `subprocess.run(..., shell=False)`
- `shlex.split` command parsing
- command allowlist via `OBSERVATION_TERMINAL_ALLOWLIST`
- working-directory containment inside `OBSERVATION_REPO_ROOT`
- timeout handling with exit code `124`
- output truncation
- explicit rejection of shell control syntax such as `&&`, `|`, `;`, redirects, backticks, and `$()`

Audit examples now covered:

- `sh -c pwd` is rejected.
- `rm -rf /tmp/example` is rejected.
- `cat .env` is rejected.
- `git status && whoami` is rejected.

### 2.3 Observability Hooks

Added observability support for the Observation Service:

- **Langfuse**:
  - Optional config through `LANGFUSE_HOST`, `LANGFUSE_PUBLIC_KEY`, and `LANGFUSE_SECRET_KEY`.
  - `/chat` creates a `terminal_chat` trace and `terminal_command_plan` generation when keys are configured.
  - Missing Langfuse keys do not prevent the service from running.

- **SigNoz / OpenTelemetry**:
  - Optional OTLP export through `OTEL_EXPORTER_OTLP_ENDPOINT`.
  - FastAPI instrumentation is enabled.
  - Custom spans are created for terminal chat and terminal API execution.

- **Structured logs**:
  - JSON stdout logs include trace/span IDs when an OpenTelemetry span is active.
  - Terminal logs include command, duration, exit code, and source app ID.
  - Query logs include row count and execution duration.

### 2.4 SQL Safety

Added a small SQL guard for `/query`:

- Allows one statement only.
- Allows only `SELECT`, `SHOW`, and `DESCRIBE`.
- Rejects write/destructive SQL such as `DROP`, `INSERT`, `ALTER`, and multi-statement requests.
