## 3. Local Telemetry Ingestion Guide (MinIO & Langfuse/SigNoz Standardization)

To integrate telemetry data from each member's local application into this centralized DWH, follow the steps below.

### 3.1 Pushing Data to MinIO
All telemetry uploads to MinIO must be grouped in batches. The Airflow pipeline requires **both** the JSONL data files and a manifest file to ingest successfully.

#### A. Path Convention
Files must be uploaded to the `agentic-bi-raw` bucket using this exact directory structure:
1. **JSONL Data files**: `raw/<source_app_id>/<source_table>/<batch_id>.jsonl`
2. **Batch Manifest file**: `raw/<source_app_id>/_manifests/<batch_id>.json`

*Where:*
- `<source_app_id>`: Must be one of `hoang_ai_chat`, `an_ai_chat`, `tuan_ai_chat`, `bach_ai_chat`.
- `<source_table>`: Must be one of the 5 canonical tables: `user_interactions`, `langfuse_generations`, `signoz_logs`, `signoz_traces`, `signoz_metrics`.
- `<batch_id>`: A unique UUID generated for that push (e.g. `uuid.uuid4()`).

#### B. Manifest Format
The manifest file is mandatory. Place it at `raw/<source_app_id>/_manifests/<batch_id>.json`:
```json
{
  "schema_version": "1.0",
  "seed_version": "sprint1-minio-v2",
  "batch_id": "<UUID>",
  "source_app_id": "<source_app_id>",
  "generated_at": "<ISO_8601_TIMESTAMP_UTC>",
  "objects": [
    {
      "source_table": "signoz_logs",
      "object_name": "raw/<source_app_id>/signoz_logs/<batch_id>.jsonl",
      "row_count": 10,
      "content_type": "application/jsonl"
    },
    ...
  ],
  "row_counts": {
    "signoz_logs": 10,
    "signoz_traces": 10,
    ...
  }
}
```

### 3.2 Telemetry Data Schema Standardization

Every row inside the JSONL files must conform to the target columns below. If you extract data from your local Langfuse or SigNoz instances, you must map their fields to these definitions:

#### A. Langfuse Schema Mapping
1. **`langfuse_generations`** (Tracks specific LLM generation details):
   - `generation_id` (String): Unique identifier from Langfuse.
   - `trace_id` (String): The parent trace ID (joins with interaction & system logs).
   - `timestamp` (ISO Datetime string): Time of generation.
   - `model` (String): Model name. **Standardize names** to: `gpt-4o`, `gpt-4o-mini`, `gemini-2.0-flash`, `claude-3-5-sonnet`, `llama-3.1-70b` for proper cost calculations.
   - `prompt_text` (String): Input query.
   - `response_text` (String): Output response.
   - `input_tokens` / `output_tokens` / `total_tokens` (Int): Token usage statistics.
   - `estimated_cost_usd` (Float): Calculated cost.
   - `duration_ms` (Int): Latency in milliseconds.
   - `status` (String): `success` or `failed`.
   - `raw_payload` (String): JSON-formatted string of any custom attributes.

2. **`user_interactions`** (Tracks user-level chat operations):
   - Same structural fields as above (`interaction_id`, `langfuse_trace_id`, `session_id`, `user_id`, `started_at`, `ended_at`, `model`, `prompt_text`, `response_text`, `input_tokens`, `output_tokens`, `total_tokens`, `estimated_cost_usd`, `status`, `raw_payload`).

#### B. SigNoz (OpenTelemetry) Schema Mapping
Local apps instrumented with OpenTelemetry send logs, traces, and metrics to local SigNoz/ClickHouse. To export these:
1. **`signoz_logs`** (Application log logs):
   - `log_id` (String): Unique log ID.
   - `timestamp` (ISO Datetime string).
   - `trace_id` & `span_id` (String): Context identifiers. **Crucial**: `trace_id` must match the parent Langfuse trace ID to enable cross-system correlation.
   - `service_name` (String): Must match your registered service: `hoang-ai-chat`, `an-ai-chat`, `tuan-ai-chat`, or `bach-ai-chat`.
   - `severity` (String): Normalize to `INFO`, `WARN`, or `ERROR`.
   - `message` (String): The log text.
   - `raw_payload` (String): JSON-formatted string of original fields.

2. **`signoz_traces`** (Traces & latency spans):
   - `trace_id` & `span_id` (String).
   - `timestamp` (ISO Datetime string).
   - `service_name` (String): E.g., `hoang-ai-chat`.
   - `name` (String): Span action name (e.g. `ai.chat.turn`).
   - `duration_ms` (Int): Milliseconds duration of span.
   - `raw_payload` (String): JSON-formatted trace attributes.

3. **`signoz_metrics`** (Timeseries numeric data):
   - `metric_id` (String).
   - `timestamp` (ISO Datetime string).
   - `service_name` (String).
   - `metric_name` (String): E.g. `chat.turns`.
   - `metric_value` (Float): Value (e.g., `1.0`).
   - `unit` (String): `count`, `ms`, etc.
   - `attributes` (String): JSON string containing tags/attributes (e.g. `{"status": "success", "model": "gpt-4o"}`).
   - `raw_payload` (String): JSON-formatted metric packet.
